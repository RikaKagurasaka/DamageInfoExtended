# Publishing

## Repository layout

- Source and releases: `RikaKagurasaka/DamageInfoExtended`, a GitHub fork of
  `perchbirdd/DamageInfoPlugin` renamed after the fork is created. The fork
  relationship retains upstream provenance; the repository itself remains
  GPL-3.0.
- Custom Dalamud feed: `RikaKagurasaka/DalamudPlugins`. It serves
  `pluginmaster.json` from GitHub Raw. The feed does not host binaries.
- Release binary: GitHub Release asset `latest.zip` on the source repository.
  The SDK package contains the DLL, manifest, dependencies and `positionals.csv`.

The intended feed URL is:

```text
https://raw.githubusercontent.com/RikaKagurasaka/DalamudPlugins/main/pluginmaster.json
```

## Metadata

The source project is configured for `Damage Info Extended` /
`DamageInfoExtended`, GPL-3.0, API level 15, version `0.1.0.0`, repository URL
`https://github.com/RikaKagurasaka/DamageInfoExtended`, and combat/damage/
flytext/mitigation tags. The manifest is generated by DalamudPackager during
the Release build; do not hand-author the package manifest.

## Release flow

1. Complete the required live-game test matrix before publishing an installable
   release.
2. Bump `PluginVersion` and changelog in `DamageInfoPlugin.csproj`.
3. Push a matching tag such as `v0.1.0.0`. The Release workflow builds and
   uploads `DamageInfoPlugin/bin/Release/DamageInfoExtended/latest.zip` as the
   release asset named `latest.zip`.
4. Dispatch the feed repository's **Sync Damage Info Extended** workflow. It
   reads the GitHub Release asset, validates the packaged manifest, adds the
   install/update links, and commits the new `pluginmaster.json`.
5. Install the custom-repository URL in Dalamud and test an install and update
   before announcing it.

Never change an existing release asset in place. Increase the assembly version
for each release so Dalamud refreshes the installed package.
